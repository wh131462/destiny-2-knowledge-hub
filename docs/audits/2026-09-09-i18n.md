# i18n 覆盖审计（2026-09-09）

## 结论

当前是局部双语界面，尚未完成全站 i18n。导航、页脚、部分页面标题和实体名称可以切换，但核心操作流程、装备详情、内容正文及反馈消息大量保持中文。

现有 `zh` / `en` 词典各有 **116 个键**，键集合一致，静态匹配到的 `t('…')` / `translate('…')` 调用未发现缺键。主要问题在于未接入翻译的文案、固定取中文的数据展示，以及没有英文版本的编辑内容，不能靠补几个缺失键解决。

本次完成检查和清单生成，**没有修改前端翻译或业务行为**。审计基于当前工作区（包含此前未提交的改动），不是仅检查 HEAD。

## 检查方法与边界

- 扫描 `web/src` 的 46 个 Vue SFC；当前路由直接加载 18 个页面。
- 19 个 SFC 直接导入 `@/i18n`。导入与否只用于定位，不代表覆盖率；包装组件可能从子组件获得翻译能力。
- 36 个文件包含中文模板文本或静态展示属性，共 **871 处候选**。使用 Vue 模板解析器识别文本和 `aria-label`、`title`、`placeholder` 等属性，排除注释和样式。
- 871 是待复核位置数，不是独立翻译条目数或确认错误数。语言按钮、品牌、双语对照、仅中文分支中的文本也可能被计入。
- 数字不包含插值表达式、脚本常量、运行时内容、共享包或 HTML 元信息，不能据此计算全站翻译百分比。
- `ToolsView.vue`（35 处）和 `SmartLoadoutView.vue`（66 处）仍在源码中，但当前对应路由重定向到 `/builds`，应与在线页面分开安排。
- 浏览器在 `http://127.0.0.1:9999` 切换 EN，抽查首页、创建构筑、武器选择弹窗、公开构筑空状态、防具页、活动页及全局搜索。未对所有路由、异常分支和移动端进行运行时遍历。

可复查清单：[i18n-inventory.json](./i18n-inventory.json)。每条候选保留文件、行号、类型和原文。

重新生成：

```sh
node scripts/audit-i18n.js > docs/audits/i18n-inventory.json
```

脚本是只读盘点工具，返回成功不代表翻译完成；静态调用匹配不处理别名或动态键。字典格式变更后需同步调整解析逻辑。

## 主要问题

### 1. 核心构筑流程尚未接入语言状态（高优先级）

以下 6 个直接路由页面没有导入 i18n：

- `ManualLoadoutView.vue`：页面标题、职业/技能选择、武器/模组弹窗、版本筛选、保存/导入/发布反馈。
- `BuildLabView.vue`：公开构筑列表、筛选、排序、同步提示、空状态。
- `BuildDetailView.vue`：精选构筑分区、机制/获取/解锁说明。
- `CommunityBuildDetailView.vue`：社区详情、复制反馈、生成的展示模型。
- `EncyclopediaEntryView.vue`：官方/编辑实体详情、加载失败与来源信息。
- `WeaponTierListView.vue`：天梯筛选、表头、说明、详情和移动端展示。

定位：`web/src/views/ManualLoadoutView.vue:36`、`:76`、`:93`、`:126`；`web/src/views/BuildLabView.vue:69`、`:77`；`web/src/views/BuildDetailView.vue:16`；`web/src/views/CommunityBuildDetailView.vue:21`；`web/src/views/EncyclopediaEntryView.vue:23`。

`ManifestCatalogView.vue` 同样没有直接导入 i18n，但它只是 `ManifestDataCatalog` 的包装页，不能据此判为完全未接入；该子组件已切换部分官方名称/说明，仍有大量中文控件。

### 4. 编辑内容和搜索摘要没有完整英文数据（高优先级）

`localized(item)` 只能选择名称，无法翻译 `desc`、`role`、`mechanics`、`encounters`、`preparation`、`rewardNote` 等字段。

- `web/src/data/world.js`：阵营、角色、资料片和传奇大多只有英文名称，说明与身份为中文。
- `web/src/data/classes.js`：职业描述、元素重点和构筑说明直接生成中文。
- `web/src/data/glossary.js`：分类和释义以中文提供；双语术语名不等于双语解释。
- `content/catalog/*-guides.js`：活动流程、准备和奖励说明需要单独的编辑译文。
- `web/src/composables/useGlobalSearch.js` 生成单份 `description`；`web/src/components/SiteHeader.vue:165` 始终显示它。

浏览器复现：EN 模式搜索 `hunter`，结果名是 `Hunter`，摘要仍为“通过闪避、精准射击和元素减益控制战场距离。”；`Star-Eater Scales` 也显示中文说明。

本站编辑内容应补双语字段或按条目 ID 组织翻译资源。社区作者输入的名称、备注、代码等属于用户内容，应保留原文，不能作为必须强制翻译的界面文字统计。

### 5. 校验、反馈和导出没有语言通路（中高优先级）

- `packages/loadout-planner/index.js:4`、`:51`：部位/属性标签和“无要求”等输出固定中文。
- `packages/loadout-planner/validation.js:32` 及规则引擎的多处校验直接返回中文消息。
- `web/src/views/BuildWorkbenchView.vue:41`、`:66` 起：JSON 错误、保存/载入/删除/导入提示为中文。
- `web/src/utils/loadoutExportModel.js:8` 起：导出模型未接收语言，分组、装备名、属性、默认标题固定中文。
- `web/src/components/LoadoutImageExport.vue`、`CommunitySubmission.vue`、`CommunityPublishGuide.vue`：预览、下载、投稿与发布指引未接入。

应使用稳定错误码及参数在显示层翻译，避免翻译规则判断本身。特别注意 `CommunityBuildDetailView.vue:52` 通过 `message.includes('自动复制不可用')` 控制展开状态；如果只替换文案会破坏交互，应改为独立状态。

导出时应显式保存生成时的语言，保证预览、下载和社区详情使用一致规则，同时保留作者原文。

### 6. 组件库语言、日期与元信息未统一（中优先级）

- `web/src/App.vue:41` 的 `a-config-provider` 只有主题，没有 `:locale`。Ant Design Vue 当前默认语言为 `en_US`，中文模式下也可能出现英文的分页、空状态和弹窗内置文案。
- `BuildWorkbenchView.vue:162`、`ManualLoadoutView.vue:302` 固定 `zh-CN` 日期格式；构筑列表部分格式化采用浏览器默认语言，不是站点选择的语言。
- `web/index.html:8` 起的标题、description 和 OG 文案固定中文。`setLocale` 更新了 `documentElement.lang`，但没有更新这些元信息。
- 模板内 `aria-label`、`title`、占位提示也需要翻译；只改可见按钮文本无法覆盖读屏体验。

## 建议实施顺序

1. 补共享语言能力：官方/编辑记录的名称与描述选择、插值消息、日期/数字格式、Ant Design locale；明确用户内容与品牌/对照文本的例外。
2. 按核心流程修复：创建构筑及其所有弹窗 → 公共构筑列表/详情 → 词条、模组、版本条件 → 导出和投稿反馈。
3. 修复图鉴和数据中心界面，再补活动、世界观、术语等正文译文；先复用官方英文，编辑译文单独维护。
4. 增加可执行的回归标准：词典键一致、静态候选逐项审核、EN / 中文切换后的实际 DOM 检查。已有候选应明确例外，不能简单把“没有中文”作为全部页面的通过标准。

验收需涵盖：同页切换语言后已展开弹窗/选项及时更新；切换前后的 Hash、筛选值、草稿内容保持一致；中英文搜索均可用；长英文选项和 375px 窄屏可操作；空结果、加载失败、非法 JSON、复制失败、保存成功及导出均随语言显示。
